## When to use

- Fix failing pytest suite (typical signals: AssertionError).
- Precondition (reported, 5 episode(s)): project uses pytest.
- Precondition (reported, 5 episode(s)): tests passed on an earlier revision.

## When NOT to use

- Observed failure: pytest collected 0 tests: the suite relies on nose-specific test generators.
- suite uses nose test generators _(reported)_.
- suite uses a different test runner such as nose or unittest-only discovery _(reported)_.
- Environments where this procedure was observed to fail: python|ubuntu|nose=1.3|python=3.8.
- Tasks that do not match the trigger above, or where the user asked for a different approach.

## Assumptions

- Evidence covers 5 independent lineage(s) across 5 repositories; environments outside python|debian|pytest=8.3|python=3.13, python|macos|pytest=8.3|python=3.12, python|ubuntu|pytest=8.1|python=3.10, python|ubuntu|pytest=8.2|python=3.11, python|ubuntu|pytest=8.3|python=3.12 are untested.

## Procedure

1. Reproduce the failure with `python -m pytest -x -q` to stop at the first failing test.
   _Evidence: 5/5 lineages._
2. Re-run only the failing test with `python -m pytest <test-node-id> -vv` to read the full assertion diff.
   _Evidence: 5/5 lineages._
3. Inspect recent changes to the module under test with `git log -p -n 5 -- <module-path>`.
   _Evidence: 5/5 lineages._
4. Fix the root cause in the source module (not the test).
   _Evidence: 5/5 lineages._
5. Run the whole suite with `python -m pytest -q` to confirm the fix and check for regressions.
   _Evidence: 5/5 lineages._

### Decision points

- **When you observe environment (VersionMismatch), e.g. "The failure only reproduced inside the project virtualenv; dependency versions differed from the lockfile":** Compare installed packages against the lockfile with `python -m pip freeze` before changing code.
  _Evidence: 2 episode(s)._

### Approaches that failed before

- Avoid: editing test expectations to match new output _(reported)_.

## Verification

- Run `python -m pytest -q` and require exit code 0. Acceptance: full test suite passes; no test assertions weakened or tests skipped.
- Do not treat your own statement that the task is done as verification.

## Failure recovery

- If the attempt "Run `pytest -x -q` directly from the repository root" failed with ImportError: reproduce the failure with `python -m pytest -x -q` so the project root is on sys.path and the first failing test is reported.
- If verification still fails, stop, report the failing output, and do not weaken tests or checks to make them pass.
